# CloudOps Pulse — API Reference

Base URL (local): `http://localhost:8000`
Base URL (AWS deploy): see the `app_url` Terraform output, e.g. `http://<public-ip>:8000`

Interactive docs (Swagger UI): `GET /docs`
Machine-readable schema: `GET /openapi.json` (OpenAPI 3.1.0, auto-generated by FastAPI)

All examples below were verified against the live app (v1.0.0) on 2026-11-20.
Responses are JSON unless stated otherwise.

> **State is in-memory.** Registered services and check history live only in the
> running process and reset on restart. See `docs/ARCHITECTURE.md` for the
> trade-off. Check history is capped at the last 100 checks per service.

## Endpoints

| Method | Endpoint | Description |
| ------ | -------- | ----------- |
| `GET` | `/` | Service info and endpoint links |
| `GET` | `/health` | Liveness / readiness probe |
| `GET` | `/metrics` | Prometheus text metrics |
| `GET` | `/api/services` | List registered services |
| `POST` | `/api/services` | Register a service |
| `GET` | `/api/services/{name}` | Get one service |
| `DELETE` | `/api/services/{name}` | Remove a service |
| `GET` | `/api/services/{name}/check` | Run a real HTTP check now |

## `GET /` — service info

```bash
curl http://localhost:8000/
```

```json
{
  "service": "CloudOps Pulse",
  "version": "1.0.0",
  "description": "Service uptime and health monitoring API",
  "docs": "/docs",
  "health": "/health",
  "metrics": "/metrics",
  "services_endpoint": "/api/services"
}
```

## `GET /health` — liveness probe

Used by the Docker `HEALTHCHECK` and by `scripts/health-check.sh`.

```bash
curl http://localhost:8000/health
```

```json
{
  "status": "healthy",
  "version": "1.0.0",
  "uptime_seconds": 3.51,
  "timestamp": "2026-11-20T06:47:04.294584+00:00",
  "services_registered": 0
}
```

| Field | Meaning |
| ----- | ------- |
| `status` | Always `"healthy"` while the process answers |
| `uptime_seconds` | Seconds since process start |
| `timestamp` | UTC time of the response |
| `services_registered` | How many services are currently registered |

## `GET /metrics` — Prometheus metrics

Plain-text Prometheus exposition format (`text/plain; version=0.0.4`),
implemented by hand in `app/main.py` — no client library. Prometheus scrapes
it every 15s (see `monitoring/prometheus.yml`).

```bash
curl http://localhost:8000/metrics
```

```
# HELP cloudops_requests_total Total HTTP requests received
# TYPE cloudops_requests_total counter
cloudops_requests_total 9
# HELP cloudops_health_checks_total Total /health calls
# TYPE cloudops_health_checks_total counter
cloudops_health_checks_total 1
# HELP cloudops_service_checks_total Total upstream service checks performed
# TYPE cloudops_service_checks_total counter
cloudops_service_checks_total 1
# HELP cloudops_service_checks_up Upstream checks classified up
# TYPE cloudops_service_checks_up counter
cloudops_service_checks_up 1
# HELP cloudops_service_checks_down Upstream checks classified down
# TYPE cloudops_service_checks_down counter
cloudops_service_checks_down 0
# HELP cloudops_services_registered Currently registered services
# TYPE cloudops_services_registered gauge
cloudops_services_registered 1
# HELP cloudops_uptime_seconds Seconds since process start
# TYPE cloudops_uptime_seconds gauge
cloudops_uptime_seconds 12.4
# HELP cloudops_app_info Application info
# TYPE cloudops_app_info gauge
cloudops_app_info{version="1.0.0"} 1
```

| Metric | Type | Meaning |
| ------ | ---- | ------- |
| `cloudops_requests_total` | counter | Every HTTP request received (middleware counts all routes) |
| `cloudops_health_checks_total` | counter | `/health` calls |
| `cloudops_service_checks_total` | counter | `/check` runs performed |
| `cloudops_service_checks_up` / `_down` | counter | Checks classified up / down |
| `cloudops_services_registered` | gauge | Services currently registered |
| `cloudops_uptime_seconds` | gauge | Seconds since process start |
| `cloudops_app_info{version="…"}` | gauge | Always `1`, labelled with the app version |

## Services

A service has a unique `name` (1–64 characters) and a `url` that must start
with `http://` or `https://`. A fresh service has `last_status: null` and
`uptime_percent: 100.0` — no failures recorded yet, not "perfect uptime".

### `POST /api/services` — register a service

```bash
curl -X POST http://localhost:8000/api/services \
  -H 'Content-Type: application/json' \
  -d '{"name": "example", "url": "https://example.com"}'
```

`201 Created`:

```json
{
  "name": "example",
  "url": "https://example.com",
  "created_at": "2026-11-20T06:47:04.311705+00:00",
  "last_status": null,
  "uptime_percent": 100.0
}
```

Errors:

| Status | When | Example detail |
| ------ | ---- | -------------- |
| `409` | Name already registered | `Service 'example' already exists` |
| `422` | URL does not start with `http://` / `https://`, or name/url missing or invalid | `url must start with http:// or https://` |

### `GET /api/services` — list services

```bash
curl http://localhost:8000/api/services
```

```json
{
  "count": 1,
  "services": [
    {
      "name": "example",
      "url": "https://example.com",
      "created_at": "2026-11-20T06:47:04.311705+00:00",
      "last_status": null,
      "uptime_percent": 100.0
    }
  ]
}
```

`uptime_percent` is computed from the service's check history
(`100.0` when no checks have run yet).

### `GET /api/services/{name}` — get one service

```bash
curl http://localhost:8000/api/services/example
```

Returns the same service object as above. Unknown name → `404` with
`{"detail": "Service 'nope' not found"}`.

### `DELETE /api/services/{name}` — remove a service

```bash
curl -X DELETE http://localhost:8000/api/services/example
```

`204 No Content`, empty body. Unknown name → `404`. Deleting also drops the
service's check history.

## `GET /api/services/{name}/check` — run a check now

Performs a real HTTP `GET` against the registered URL (3-second timeout,
`User-Agent: CloudOpsPulse/1.0`, reads at most 512 bytes of the body) and
records the result in the service's history.

```bash
curl http://localhost:8000/api/services/example/check
```

```json
{
  "name": "example",
  "url": "https://example.com",
  "status": "up",
  "status_code": 200,
  "latency_ms": 570.02,
  "latency_class": "slow",
  "healthy": true,
  "error": null,
  "checked_at": "2026-11-20T06:47:04.963431+00:00",
  "uptime_percent": 100.0
}
```

| Field | Meaning |
| ----- | ------- |
| `status` | `"up"` for 2xx/3xx, `"down"` for 4xx/5xx or when no response was received |
| `status_code` | HTTP status received, or `null` when unreachable (DNS failure, timeout, TLS error) |
| `latency_ms` | Round-trip time in milliseconds |
| `latency_class` | `"fast"` (< 200 ms), `"slow"` (< 1000 ms), `"critical"` (≥ 1000 ms), `"unknown"` (no measurement) |
| `healthy` | `true` only when the service is up, latency ≤ 5000 ms, and no connection error occurred |
| `error` | Error string (e.g. `URLError: ...`) when the request failed, otherwise `null` |
| `checked_at` | UTC time of the check |
| `uptime_percent` | Uptime over the stored check history, updated by this check |

Notes:

- An HTTP error response (4xx/5xx) is still a response: `status_code` is
  recorded and `status` is `"down"`, but `error` stays `null`.
- An unreachable service records `status: "down"`, `status_code: null`, and
  the error in `error`.
- Unknown service name → `404`.

## Error format

All errors are FastAPI `HTTPException`s:

```json
{"detail": "Service 'nope' not found"}
```

Validation errors (bad request body) use the same shape with a `detail` list
of validation problems.
